# Post-Meal & Ratings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** After a meal, both matched parties confirm show-up + rate each other (1–5 stars, optional comment); ratings aggregate onto the target's user doc via a Cloud Function; a scheduled Function drives a post-meal push.

**Architecture:** A new `rating` feature (Pragmatic Clean). Ratings are `ratings/{matchId}_{raterUid}`, immutable, participant-only, read-own. A Cloud Function aggregates onto `users/{uid}` (`ratingCount`/`ratingSum`/`ratingAvg`), which clients cannot write. A scheduled Function pushes a post-meal reminder + flips matched meals to `completed`. In-app: a post-meal card + rating sheet + an aggregate badge.

**Tech Stack:** Flutter 3.47.4 (FVM), freezed 4 + json_serializable, Riverpod, cloud_firestore, go_router; Cloud Functions TypeScript (firebase-functions v2 firestore + scheduler, firebase-admin); flutter_test + mocktail + fake_cloud_firestore; jest.

**Design spec:** `docs/superpowers/specs/2026-09-23-ratings-design.md`

## Global Constraints

- Always `fvm flutter` / `fvm dart`; `$HOME/.pub-cache/bin` on PATH. Node 20 for Functions.
- Dependency rule: `presentation → application → domain ← data`. `cloud_firestore` only in `rating/data/`. `domain/` pure.
- DTO/mapper + `Timestamp`↔`DateTime` conventions as elsewhere; repos throw `RepositoryWriteException`. `ref.watch` only in build/provider bodies.
- Analytics via the typed registry; no PII (stars/showed_up are fine; never a uid/comment as a prop). Tokens for UI. Tests mirror `lib/`.
- Codegen after freezed/`@riverpod`: `fvm dart run build_runner build --delete-conflicting-outputs`.
- Firestore single project; rules deploy to both DBs. Functions build/test via `npm --prefix firebase/functions`.
- Aggregate + post-meal push need Blaze + (schedule) Cloud Scheduler — build/unit-test now, live is gated on Blaze.

```
    match /ratings/{ratingId} {
      allow read: if isSignedIn() && resource.data.raterUid == request.auth.uid;
      allow create: if isSignedIn()
                    && request.resource.data.raterUid == request.auth.uid
                    && request.resource.data.raterUid != request.resource.data.targetUid

                    && ratingParticipantsValid(request.resource.data.matchId,
                                               request.resource.data.raterUid,
                                               request.resource.data.targetUid);
      allow update, delete: if false;
    }
```

```
    function ratingParticipantsValid(matchId, rater, target) {
      let m = get(/databases/$(database)/documents/matches/$(matchId)).data;
      return (rater == m.hostId && target == m.guestId)
          || (rater == m.guestId && target == m.hostId);
    }
```

- [ ] **Step 2: Implement `aggregate.ts`.**

```ts
// firebase/functions/src/lib/aggregate.ts
export function nextAggregate(prevSum: number, prevCount: number, stars: number): {
  sum: number; count: number; avg: number;
} {
  const sum = prevSum + stars;
  const count = prevCount + 1;
  return { sum, count, avg: sum / count };
}
```

- [ ] **Step 3: Trigger `rating_created.ts`** (factory per database):

```ts
import { onDocumentCreated } from 'firebase-functions/v2/firestore';
import { getApp } from 'firebase-admin/app';
import { getFirestore } from 'firebase-admin/firestore';
import { nextAggregate } from '../lib/aggregate';

export const makeRatingCreated = (database: string) =>
  onDocumentCreated(
    { document: 'ratings/{ratingId}', database, region: 'europe-west1' },
    async (event) => {
      const data = event.data?.data();
      const targetUid = data?.targetUid as string | undefined;
      const stars = data?.stars as number | undefined;
      if (!targetUid || typeof stars !== 'number') return;
      const db = getFirestore(getApp(), database);
      const userRef = db.collection('users').doc(targetUid);
      await db.runTransaction(async (txn) => {
        const snap = await txn.get(userRef);
        const prev = snap.data() ?? {};
        const agg = nextAggregate(
          (prev.ratingSum as number) ?? 0,
          (prev.ratingCount as number) ?? 0,
          stars,
        );
        txn.set(userRef, {
          ratingSum: agg.sum, ratingCount: agg.count, ratingAvg: agg.avg,
        }, { merge: true });
      });
    },
  );
```

```ts
// firebase/functions/src/scheduled/post_meal_reminder.ts
import { onSchedule } from 'firebase-functions/v2/scheduler';
import { getApp } from 'firebase-admin/app';
import { getFirestore, Timestamp } from 'firebase-admin/firestore';
import { sendToUser } from '../lib/messaging';
import { buildPostMealPrompt } from '../lib/payloads';

export const makePostMealReminder = (database: string) =>
  onSchedule(
    { schedule: 'every 60 minutes', region: 'europe-west1' },
    async () => {
      const db = getFirestore(getApp(), database);
      const now = Timestamp.now();
      const snap = await db.collection('meals')
        .where('status', '==', 'matched')
        .where('dateTime', '<=', now)
        .get();
      for (const doc of snap.docs) {
        const m = doc.data();
        if (m.postMealNotified === true) continue;
        const hostId = m.hostId as string | undefined;
        const guestId = m.guestId as string | undefined;
        const matchId = doc.id;
        const payloadFor = (name: string) => {
          const p = buildPostMealPrompt(name);
          p.data.matchId = matchId;
          return p;
        };
        if (hostId) await sendToUser(database, hostId, payloadFor('your match'));
        if (guestId) await sendToUser(database, guestId, payloadFor('your match'));
        await doc.ref.set({ status: 'completed', postMealNotified: true }, { merge: true });
      }
    },
  );
```

(A single `where('dateTime','<=',now)` + the `postMealNotified` flag guard is enough; the query needs a `status`+`dateTime` composite index — reuse/add in `firestore.indexes.json` if the existing discovery index doesn't cover it. If an index is required, add it.)
