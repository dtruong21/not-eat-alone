# Convyve — Plan 3: Profile Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** After the 18+ gate, a user must complete a profile (display name, ≥1 photo, gender) before reaching home; profiles are editable; photos live in a shared Firebase Storage bucket under env-prefixed paths.

**Architecture:** Extend the clean `user` feature — `AppUser` entity + DTO gain profile fields with a derived `profileComplete`; a `UserRepository.updateProfile` merge-writes them; a `PhotoStorageDataSource` handles Storage I/O under `{storagePathPrefix}/users/{uid}/...`; a `ProfileController` (AsyncNotifier) drives a shared form used by the forced onboarding setup screen and the settings edit screen; the router gains a 4th state (incomplete profile → forced setup, no skip).

**Tech Stack:** Flutter 3.47.4 (FVM), Riverpod, freezed 4, cloud_firestore, firebase_storage, image_picker, flutter_image_compress, go_router, mocktail, fake_cloud_firestore.

**Base branch:** `rename-convyve` (this branch, `plan-3-profile`, is stacked on it).

```
rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    // Per-env, per-user profile photos. `env` is 'stage' or 'prod'.
    match /{env}/users/{uid}/{file} {
      allow read: if request.auth != null;
      allow write: if request.auth != null
                   && request.auth.uid == uid
                   && request.resource.size < 8 * 1024 * 1024
                   && request.resource.contentType.matches('image/.*');
      allow delete: if request.auth != null && request.auth.uid == uid;
    }
    match /{allPaths=**} { allow read, write: if false; }
  }
}
```
