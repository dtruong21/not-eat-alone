# Weekly reviews

Output dir for `/weekly-review`. One file per week: `YYYY-MM-DD.md` (the Monday of that week).

## Why this exists

Solo devs lose track of which-feature-is-where without a forcing function. The weekly review is 15 minutes to:

- See what shipped (often more than you remember)
- See what didn't (often more than you'd like)
- Flag burnout before it hits
- Pick 3 things for the next week

It's a journal, not a report. Nobody else reads it. The value is in writing it.

## Cadence

Run `/weekly-review` every Monday morning before any other work. If you skip a Monday, run it Tuesday — but don't compound by skipping two weeks.

## What stays here

All weekly reviews. Don't archive. The history is the point — going back 8 weeks shows you patterns (the same feature keeps slipping, you keep working 60h weeks, etc.) that single-week reviews miss.
